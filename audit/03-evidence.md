## The eight load-bearing claims

| # | claim | verdict | in one line | detail |
|---|---|---|---|---|
| a | `create or replace function` resets grants | **FALSE** | PostgreSQL 12–18: "the ownership and permissions of the function do not change". The real trap is drop+create or a changed signature, which creates a new function with default privileges. | 03-evidence-b § (a) |
| b | `revoke … from public` insufficient without `alter default privileges` | TRUE-WITH-CAVEAT | True on Supabase because its init SQL grants all on functions to `anon`, `authenticated` by default privileges, not because of "public roles", a phrase that collides with PostgreSQL `PUBLIC`. Default-privilege entries are per grantor role. | 03-evidence-b § (b) |
| c | A `disabled` field is omitted from `FormData`, save reads it as cleared | TRUE-WITH-CAVEAT | HTML § 4.10.22.4 excludes disabled controls from the entry list; the field is *absent*, "cleared" is the handler's doing. `readonly` controls are submitted. A hidden `required` field blocks submission silently. | 03-evidence-c § c |
| d | Only the real build catches a non-serializable server→client value | TRUE-WITH-CAVEAT | The build's real advantage is prerendering every route unvisited; dev throws on visited routes and the Next.js TS plugin flags function props. A green build is not a ceiling either. | 03-evidence-a § (d) |
| e | `build \| tail` returns tail's exit status | TRUE (POSIX Issue 8 § 2.9.2) | On PowerShell the prescribed remedy `$?` is itself masked; `$LASTEXITCODE` is the right variable. | 03-evidence-a § (e) |
| f | TTL-only caching turns a delay into stale data; tags + co-located invalidation is the fix | TRUE in substance, VERSION-STALE in API | RFC 9111 separates freshness from invalidation; Next.js says TTL and tags "are often paired". But `unstable_cache` is replaced in Next.js 16, `revalidateTag` needs a second argument, and `updateTag` throws outside a Server Action, so "invalidate inside the shared service" can throw on the webhook path. | 03-evidence-a § (f) |
| g | Timestamps re-read as `+00:00` vs `Z` make `!==` always true | TRUE-WITH-CAVEAT | Holds for string comparison of differently serialized values (Postgres emits `+00`, `toISOString` emits `Z`; RFC 3339 § 4.3 says both are UTC). Compared as instants they are equal. | 03-evidence-b § (g) |
| h | An email provider rejecting `tags: []` kills one message family | COULD NOT VERIFY → class C | No provider named; Resend's API and error references document no such rejection. The instruction (omit when empty; test the channel live) stands; the causal story must be labeled n=1. | 03-evidence-b § (h) |
